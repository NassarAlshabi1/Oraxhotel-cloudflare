# ملاحظات تدقيق إعادة هيكلة واجهة Flutter

## الوضع الحالي

نقطة الدخول `lib/main.dart` تحتوي على مسؤوليات تشغيلية كثيرة، بينما `RootRouter` و`HomeShell` يديران المصادقة والتنقل والصلاحيات وبناء الصفحات في الملف نفسه. قائمة المسارات مكررة مرة في `HomeShell._validRoutes/_buildRoute` ومرة أخرى في `AdminSidebar` مع فحص صلاحيات مستقل.

`AdminLayout` يختار تخطيط sidebar للشاشات بعرض 768 فأكثر وdrawer للأجهزة الأصغر، بينما `AppScaffold` يكرر Scaffold وAppBar وإجراء الإشعارات والمزامنة داخل الشاشات الداخلية.

شاشة `PaymentsMainScreen` تجمع تبويبات الشاشة، تحميل البيانات عبر repositories، الإحصاءات، التحليلات، Crashlytics، الحوار، حفظ الدفع، وتفعيل المزامنة داخل State واحد. وهي أفضل نقطة تجريبية لفصل feature shell عن controller/view-model والمكونات المرئية.

## قرار مبدئي

سيكون محور الهيكلة هو تعريف مركزي لـ `AppRoute` و`NavigationItem`، ثم جعل `HomeShell` و`AdminSidebar` يقرآن نفس التعريف. بعد ذلك يُفصل منطق شاشة المدفوعات تدريجياً دون تغيير عقود repositories أو منطق Drift/Outbox.

## قيود يجب احترامها

يجب عدم نقل منطق المزامنة إلى widgets، وعدم حذف المسار القديم قبل وجود بديل اختباري. كما يجب الحفاظ على RTL والتخطيط المتجاوب والصلاحيات الحالية. لا يجوز الادعاء بنجاح تحليل Dart قبل توفر `dart` أو `flutter` في البيئة.

## التنفيذ الحالي

أُنشئ `core/navigation/app_routes.dart` كمصدر مركزي لتعريف 14 مساراً رئيسياً مع العنوان والصلاحية والأيقونة وباني الصفحة. أُعيدت كتابة `AdminSidebar` ليقرأ هذا التعريف بدلاً من قائمة مستقلة، وأصبح `HomeShell` و`RootRouter` في ملفات navigation مستقلة عن `main.dart`.

فُصل غلاف تبويبات المدفوعات إلى `screens/payments/widgets/payments_main_shell.dart`. أصبحت الشاشة الأصلية مسؤولة عن بيانات المدفوعات وعمليات الحفظ، بينما يدير الغلاف TabController وAppScaffold وFAB والتبويبات. لم تتغير عقود repositories أو Drift أو المزامنة.
