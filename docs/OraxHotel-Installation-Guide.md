# دليل تثبيت وتشغيل وإدارة Orax Hotel

**اسم المنتج:** Orax Hotel

**ملف التثبيت:** `OraxHotel-Setup.exe`

**نوع النظام:** تطبيق ويب محلي يعمل على Windows، وليس تطبيق سطح مكتب تقليديًا.

**إصدار النشر:** Windows x64، نشر ذاتي التشغيل Self-contained.

**عنوان التشغيل المحلي:** `http://localhost:5080`

---

## 1. نظرة عامة على النظام

Orax Hotel هو نظام إدارة فندق مبني على ASP.NET Core، ويعمل كخادم محلي على جهاز Windows. بعد تشغيله يفتح المستخدم المتصفح للوصول إلى الواجهة، بينما تُحفظ بيانات الفندق والمستخدمين في قاعدة SQL Server باسم `Hotel_alkheer`.

يحتوي النظام على وحدات الاستقبال والحجوزات والغرف والعملاء والفواتير والسندات والحسابات والخدمات والتقارير والإعدادات العامة وتقارير الصندوق والعملاء. كما يضم أدوات إنشاء QR والتقارير وملفات الواجهة المجمعة داخل `wwwroot`.

> **مهم:** ملف EXE الشامل يضمّن نظام Orax Hotel ووسيط SQL Server 2022 Express x64 وملفات قاعدة البيانات. سيطلب Windows صلاحية Administrator عبر UAC، ثم يثبت محرك SQL Server محلياً عند عدم وجود `SQLEXPRESS`. لا يحتاج الجهاز إلى تثبيت SQL Server يدوياً قبل تشغيل الملف، لكن يجب أن يكون Windows 64-bit وأن تتوفر مساحة كافية.

| العنصر | الوظيفة |

## 3. المتطلبات قبل التثبيت

يُنصح باستخدام Windows 10 أو Windows 11 بنظام 64-bit. المُثبّت الشامل يثبت SQL Server 2022 Express محلياً عند الحاجة ويستخدم النسخة المسماة `SQLEXPRESS`. لا يلزم تثبيت SQL Server مسبقاً. إذا كان الجهاز يحتوي على نسخة `SQLEXPRESS` قابلة للاتصال، يحافظ المُثبّت عليها ولا يعيد تثبيتها.

```text
.\SQLEXPRESS
```

النسخة الشاملة الحالية لا تعرض حقلاً لاختيار خادم خارجي؛ فهي مبرمجة لاستخدام خدمة SQL Server المحلية المسماة `SQLEXPRESS` عبر:

```text
.\SQLEXPRESS
```

إذا كان الجهاز يستخدم SQL Server باسم مختلف أو قاعدة مركزية على الشبكة، فلا تعتبر هذه الحزمة مناسبة دون تعديل برمجي واختبار مستقل. يجب تشغيل المُثبّت باستخدام **Run as administrator**، لأن تثبيت SQL Server واستعادة قاعدة البيانات يحتاجان صلاحيات Windows مرتفعة.

قبل التثبيت على جهاز يحتوي على قاعدة سابقة، خذ نسخة احتياطية من قاعدة `Hotel_alkheer`. لا تستخدم خيار الاستعادة فوق قاعدة قائمة دون التأكد من البيانات، لأن الاستعادة قد تستبدل ملفات قاعدة البيانات إذا نفذها المستخدم يدويًا.

## 4. خطوات تثبيت النظام

### 4.1 تشغيل المُثبّت

شغّل الملف:

```text
OraxHotel-Setup.exe
```

سيقوم المُثبّت بفك ملفات التطبيق داخليًا، ثم ينسخها إلى:

```text
%LOCALAPPDATA%\OraxHotel
```

ولا يحتاج نسخ ملفات التطبيق إلى مجلد `Program Files`. أما نسخة قاعدة البيانات الاحتياطية التي تُستخدم للاستعادة فتُنسخ إلى:

```text
%ProgramData%\OraxHotel\Database
```

### 4.2 إدخال خادم SQL Server

يستخدم المُثبّت الشامل تلقائياً الخادم المحلي ` .\SQLEXPRESS `. لا يظهر سؤال اسم الخادم في النسخة الشاملة؛ إذ إن المحرك يُثبت ويُهيأ محلياً. إذا كان لديك إصدار مخصص من المُثبّت القديم الذي يطلب الخادم، فالقيمة الافتراضية هي:

```text
.\SQLEXPRESS
```

### 4.3 المصادقة التي تستخدمها النسخة الشاملة

النسخة الشاملة الحالية تستخدم **Windows Integrated Security** لحساب Windows الذي شغّل المُثبّت. لا توجد شاشة لإدخال اسم مستخدم SQL أو كلمة مرور SQL، ولا يستخدم المثبت حساب `sa`. أثناء تثبيت SQL Server Express يُضاف حساب Windows الحالي كحساب SQL Server إداري حتى يتمكن المثبت من إنشاء أو استعادة قاعدة `Hotel_alkheer`.

بعد كتابة الإعدادات، يحتوي الاتصال المحلي على `Integrated Security=True` و`TrustServerCertificate=True`، ولا تُكتب كلمة مرور SQL في `appsettings.json`. أما استخدام SQL Server خارجي أو SQL Authentication فيتطلب إصداراً مخصصاً لم يُختبر ضمن هذه الحزمة.

### 4.4 استعادة قاعدة البيانات

بعد نجاح الاتصال، يبحث المُثبّت عن قاعدة `Hotel_alkheer`.

إذا لم تكن القاعدة موجودة، يستعيد النسخة الاحتياطية المضمنة. بهذه الطريقة تبقى جداول المستخدمين وبيانات المشرف وصاحب النظام كما كانت في النسخة الأصلية.

إذا كانت قاعدة `Hotel_alkheer` موجودة مسبقًا، لا يستبدلها المُثبّت ولا ينشئ حسابًا جديدًا. تظهر رسالة تفيد بأن القاعدة الموجودة تم الحفاظ عليها.

إذا لم تتوفر النسخة الاحتياطية داخل payload، يوجد ملف بديل باسم `Hotel_alkheer_init.sql`. هذا الملف ينشئ 47 جدولًا والبيانات الأولية العامة، لكنه **لا ينشئ مستخدمًا ولا كلمة مرور**؛ لذلك لا يمكنه الحفاظ على حساب المشرف الأصلي. إذا كانت النسخة الاحتياطية موجودة لكنها فشلت أثناء الاستعادة، يوقف المُثبّت العملية بدلاً من استبدالها بقاعدة بلا حساب المشرف، ويجب فحص سجل SQL أو توفير نسخة احتياطية صحيحة.

### 4.5 إكمال التثبيت

بعد التثبيت يُنشئ المُثبّت اختصارًا باسم:

```text
Orax Hotel
```

على سطح المكتب. يمكن أيضًا تشغيل النظام من:

```text
%LOCALAPPDATA%\OraxHotel\start-oraxhotel.cmd
```

## 5. تشغيل النظام وتسجيل الدخول

افتح اختصار **Orax Hotel**. يبدأ الخادم المحلي ثم يفتح المتصفح على:

```text
http://localhost:5080
```

بعد ظهور شاشة الدخول، أدخل بيانات **المشرف أو صاحب النظام الموجودة مسبقًا في قاعدة البيانات المستعادة**.

لا توجد كلمة مرور عامة أو افتراضية في هذا الدليل، ولا يقوم المُثبّت بإنشاء مستخدم `admin` جديد. اسم المستخدم قد يكون `admin` أو اسمًا عربيًا أو اسمًا آخر بحسب السجل الموجود في النسخة الاحتياطية؛ لذلك لا ينبغي افتراض الاسم دون الرجوع إلى صاحب النظام أو مسؤول قاعدة البيانات.

### بيانات الدخول المطلوبة عند فتح التطبيق

| الحقل | القيمة الآمنة |
|---|---|
| اسم المستخدم | اسم حساب المشرف/صاحب النظام الموجود مسبقًا في `dbo.AspNetUsers` داخل النسخة الاحتياطية؛ لا يتم افتراض قيمة ثابتة |
| كلمة المرور | كلمة المرور الأصلية التي يعرفها صاحب النظام؛ لا تُكتب في GitHub أو ملف التعليمات أو ملف SQL |
| حساب SQL Server | حساب تقني يستخدمه المُثبّت للاستعادة فقط، وليس حساب دخول إلى التطبيق |

إذا كان اسم المستخدم معروفًا لدى صاحب النظام، يُدخله في شاشة الدخول كما هو، مع مراعاة الأحرف والمسافات. لا تُرسل كلمة المرور عبر GitHub ولا تُضمّنها داخل `appsettings.json`. عند الحاجة إلى تغييرها، استخدم وظيفة تغيير كلمة المرور داخل Identity أو نفّذ إجراء استعادة رسميًا بواسطة مسؤول النظام.

إذا لم تظهر شاشة الدخول، تحقق من أن التطبيق يعمل وأن المتصفح يفتح العنوان الصحيح. وإذا ظهرت شاشة الدخول لكن بيانات المشرف لا تعمل، فهذا يعني غالبًا أن قاعدة مختلفة تم الاتصال بها أو أن النسخة الاحتياطية المستعادة ليست النسخة التي تحتوي على حساب المشرف المطلوب.

## 6. أسماء الحسابات والأدوار

### 6.1 حساب المشرف/صاحب النظام

الحساب الرئيسي هو الحساب الموجود في جدول ASP.NET Identity، وبالأخص جدول:

```text
dbo.AspNetUsers
```

تُحفظ كلمة المرور في هذا الجدول على شكل `PasswordHash`، وليس كنص واضح. يستعيد المُثبّت الحساب كما هو من نسخة `.bak` ولا يغير الاسم أو كلمة المرور أو hash.

### 6.2 الحسابات القديمة

يحتوي مخطط النظام أيضًا على جدول قديم باسم:

```text
dbo.user_table
```

قد يحتوي هذا الجدول على حسابات قديمة مرتبطة بتصميم سابق للنظام. لا ينبغي الخلط بينه وبين حسابات ASP.NET Identity المستخدمة في شاشة الدخول الحالية. شاشة الدخول الحالية تتحقق من `AspNetUsers.PasswordHash` باستخدام `PasswordHasher` ثم تنشئ Cookie Authentication؛ وتحتفظ بتوافق احتياطي مع الحسابات القديمة في `admin_table`.

### 6.3 أسماء الأدوار المحتملة

تظهر في بعض أجزاء الكود إشارات إلى أدوار مثل:

```text
admin
accounting
ITmanager
```

لكن بعض قيود الأدوار في المتحكمات موجودة على شكل تعليقات، بينما الحماية الفعلية الظاهرة في معظم الوحدات هي `[Authorize]`، أي اشتراط تسجيل الدخول. لذلك يجب اعتبار الأسماء السابقة أدوارًا محتملة في البيانات أو تصميمًا مستقبليًا، وليس ضمانًا بأن كل وظيفة تطبق صلاحية الدور بصورة مستقلة.

### 6.4 مسؤول قاعدة البيانات

حساب SQL Server المستخدم أثناء التثبيت ليس حساب دخول إلى تطبيق الفندق. هو حساب تقني يستخدمه المُثبّت لاستعادة قاعدة البيانات. يجب عدم استخدام بيانات SQL Server في شاشة دخول Orax Hotel.

## 9. ملفات الإعداد

بعد التثبيت يوجد الملف:

```text
%LOCALAPPDATA%\OraxHotel\appsettings.json
```

يكتب المُثبّت داخله اتصال SQL Server الذي أدخله المستخدم. يحتوي القالب قبل التثبيت على اتصالات SQLite المحلية فقط، ولا يحتوي على كلمات مرور أو عناوين خوادم بعيدة ثابتة.

مفاتيح الاتصال الأساسية هي:

| المفتاح | الاستخدام |
|---|---|
| `cc` | الاتصال الرئيسي الذي تستخدمه طبقة Linq2DB |
| `Hotel_alkheerContext` | اتصال Entity Framework وASP.NET Identity |
| `NWindConnectionString` | قاعدة SQLite المرفقة للتقارير/العرض |
| `ReportsDataConnectionString` | قاعدة SQLite المحلية للتقارير |

يجب عدم رفع ملف `appsettings.json` بعد التثبيت إلى مستودع عام إذا كان يحتوي على SQL Authentication، لأنه قد يحتوي على كلمة مرور اتصال.

## 10. النسخ الاحتياطي والاستعادة

### 10.1 النسخ الاحتياطي قبل التحديث

يجب أخذ نسخة احتياطية قبل إعادة التثبيت أو تحديث التطبيق. يمكن لمسؤول قاعدة البيانات استخدام SQL Server Management Studio أو أمر T-SQL مكافئ وفق سياسة المؤسسة.

مثال توضيحي يجب مراجعته قبل التنفيذ:

```sql
BACKUP DATABASE [Hotel_alkheer]
TO DISK = N'D:\Backups\Hotel_alkheer_before_upgrade.bak'
WITH INIT, COMPRESSION, CHECKSUM;
```

### 10.2 مكان نسخة المُثبّت

يحتفظ المُثبّت بنسخة قاعدة البيانات في:

```text
%ProgramData%\OraxHotel\Database\Hotel_alkheer_seed.bak
```

أما ملفات التطبيق فتوجد في:

```text
%LOCALAPPDATA%\OraxHotel
```

### 10.3 إلغاء التثبيت

تشغيل `uninstall-oraxhotel.cmd` يزيل ملفات التطبيق والاختصار. لا يفترض أن يحذف قاعدة `Hotel_alkheer` أو نسخة `.bak` من SQL Server، لأن حذف قاعدة البيانات أثناء إزالة البرنامج قد يؤدي إلى فقدان بيانات الفندق.

## 11. الاستكشاف وإصلاح المشكلات

### المشكلة: لا يمكن الاتصال بـ SQL Server

إذا فشل تثبيت SQL Server Express، شغّل الملف من خلال **Run as administrator**، وتأكد من وجود مساحة قرص كافية وعدم وجود تثبيت SQL Server متعثر. بعد نجاح التثبيت يجب أن تكون خدمة `MSSQL$SQLEXPRESS` قابلة للتشغيل. في الإصدار الشامل يستخدم التطبيق:

```text
.\SQLEXPRESS
```

وفي SQL Server الافتراضي جرّب:

```text
.
```

### المشكلة: فشل استعادة النسخة الاحتياطية

قد يكون حساب SQL Server غير قادر على قراءة مجلد `%ProgramData%\OraxHotel\Database` أو قد تكون ملفات النسخة الاحتياطية تشير إلى مسارات قديمة. شغّل المُثبّت كمسؤول، وتأكد من أن مساحة القرص كافية، وأن النسخة الاحتياطية صالحة لنفس إصدار SQL Server أو إصدار متوافق.

### المشكلة: القاعدة موجودة لكن حساب المشرف لا يعمل

تحقق من أن التطبيق يستخدم قاعدة `Hotel_alkheer` الصحيحة، وأن `appsettings.json` بعد التثبيت يحتوي على الخادم الصحيح، وأن الحساب موجود في `dbo.AspNetUsers`. لا تنشئ حسابًا جديدًا قبل التأكد من أنك لا تتصل بقاعدة مختلفة.

### المشكلة: التطبيق يفتح ثم يغلق

افتح نافذة Command Prompt داخل مجلد التطبيق وشغّل:

```bat
HotelSys.exe
```

راقب رسالة الخطأ. أكثر الأسباب شيوعًا هي فشل SQL Server أو عدم صلاحية بيانات الاتصال أو عدم توفر ملفات التقارير أو مشكلة في ترخيص DevExpress.

### المشكلة: المنفذ 5080 مستخدم

أغلق نسخة Orax Hotel السابقة أو غيّر المنفذ في `start-oraxhotel.cmd` وداخل أمر فتح المتصفح، ثم استخدم المنفذ نفسه في العنوان المحلي.

### المشكلة: التقارير لا تعمل

تحقق من ترخيص DevExpress المطلوب، ومن وجود ملفات التقارير `.vsrepx` داخل النشر، ومن صلاحية اتصال قاعدة البيانات. لا تتم معالجة هذه المشكلة بتجاوز الترخيص.

## 12. قائمة فحص ما بعد التثبيت

| الفحص | النتيجة المطلوبة |
|---|---|
| خدمة SQL Server | تعمل ويمكن الاتصال بها |
| قاعدة `Hotel_alkheer` | موجودة أو تمت استعادتها بنجاح |
| حساب المشرف | موجود في `dbo.AspNetUsers` كما في النسخة الأصلية |
| `appsettings.json` | يحتوي اتصال الجهاز الجديد ولا يحتوي أسرارًا غير مقصودة |
| اختصار سطح المكتب | يفتح الخادم المحلي والمتصفح |
| محرك SQL Server Express | ثُبّت أو كان موجوداً، وخدمة `MSSQL$SQLEXPRESS` تعمل |
| شاشة الدخول | تظهر وتتحقق من PasswordHash الخاص بالمشرف الأصلي |
| الوحدات الأساسية | الاستقبال والغرف والعملاء والفواتير تعمل |
| التقارير | تفتح حسب ترخيص DevExpress وبياناتها |
| النسخ الاحتياطي | تم أخذ نسخة قبل أي تحديث أو استعادة |
| الأمان | تم تغيير أي كلمات مرور تقنية أو SQL افتراضية وفق سياسة المؤسسة |

## 13. معلومات الإصدار والبناء

تم إنشاء المُثبّت للمعمارية `win-x64` بصيغة Windows PE، مع نشر ذاتي التشغيل للتطبيق والمُثبّت. تم اختبار سلامة أرشيف payload وتحقق وجود التطبيق وملف النسخة الاحتياطية وملف SQL داخل الحزمة من بيئة البناء.

لم يتم تشغيل ملف EXE أو SQL Server فعليًا داخل بيئة Linux، لذلك يجب تنفيذ اختبار عملي على Windows قبل اعتماد النظام في الإنتاج، ويفضل إجراء الاختبار على نسخة تجريبية من قاعدة البيانات أولًا.

## 14. خلاصة مهمة

المسار الصحيح لتسجيل الدخول هو استخدام حساب **المشرف/صاحب النظام الموجود مسبقًا في النسخة الاحتياطية**. المُثبّت لا ينشئ `admin` جديدًا ولا يغير كلمة المرور. إذا لم تكن النسخة الاحتياطية تحتوي على حساب المشرف المطلوب، يجب توفير نسخة احتياطية صحيحة من مالك النظام بدل تخمين كلمة المرور أو إنشاء حساب غير معتمد.
